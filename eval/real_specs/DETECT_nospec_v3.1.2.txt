[VIOLATION] archive_read_support_format_mtree.c:885  sev=high
    op: memcpy(entry->name, name, len);
    The `memcpy(entry->name, name, len)` operation attempts to copy `len` bytes from the `name` pointer. There are two distinct scenarios where this can lead to an out-of-bounds read from the source buffer `name` (which is derived from the input `line`):

1.  **When `is_form_d` is false:**
    -   `name` is set to `line`.
    -   `len` is calculated using `strcspn(line, " \t\r\n")`. The `line` buffer, obtained from `__archive_read_ahead`, is *not guaranteed to be null-terminated* within its valid `line_len` boundary. If `strcspn` does not find any of the delimiter characters or a null terminator within the `line_len` bytes, it will read past `line + line_len - 1`, leading to an out-of-bounds read. If this read succeeds without crashing, `len` could be computed to be greater than `line_len`. In such a case, the subsequent `memcpy(entry->name, line, len)` would read `len` bytes from `line`, resulting in an out-of-bounds read from the `line` buffer.

2.  **When `is_form_d` is true:**
    -   The logic for parsing the name involves decrementing `name` and `line_len` in a loop to find the start of the name. Consider the edge case where the input `line` consists of a single non-whitespace character, e.g., `line = "A"` and `line_len = 1`.
        -   Initially, `name = line + line_len - 1` points to `line[0]` ('A'). `line_len` is 1.
        -   The first `while` loop (skipping trailing whitespace) does not modify `name` or `line_len` as 'A' is not whitespace.
        -   `len` is initialized to 0.
        -   The second `while` loop (`while (line_len > 0) { ... }`):
            -   `line_len` is 1, `*name` is 'A' (not whitespace).
            -   `name--` (moves `name` to `line - 1`).
            -   `line_len--` (becomes 0).
            -   `len++` (becomes 1).
            -   The loop condition `line_len > 0` is now false, so the loop terminates.
        -   At this point, `name` points to `line - 1`, and `len` is 1.
        -   The `memcpy(entry->name, name, len)` call becomes `memcpy(entry->name, line - 1, 1)`, which attempts to read 1 byte from one byte *before* the start of the valid `line` buffer, resulting in an out-of-bounds read.

In both cases, the source buffer for `memcpy` can be read out of bounds. The destination buffer `entry->name` is correctly allocated with `len + 1` bytes, so the issue is solely with the source read.
